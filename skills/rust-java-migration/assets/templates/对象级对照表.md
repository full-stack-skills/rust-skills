## 当前迁移规范执行口径

- 本文是对象完成状态的唯一当前权威台账；模板生成结果是 `DRAFT`，不得当作完成证据。
- 预期路径从 `{{JAVA_PACKAGE_ROOT}}` 起保留末 `{{RETAIN_SEGMENTS}}` 层包目录并转换为 `snake_case`；必须同时记录预期路径与当前路径。
- Spring/Java 源码决定对象、目录、文件和公共语义边界；Rust 依赖只决定哪些逻辑可精确复用，不能反向取消源对象台账。
- 只有 `IMPLEMENTED`、`DEPENDENCY_REUSED`、`PLATFORM_NA` 属于已处理；`MISSING`、`MISPLACED`、`STUB`、`PARTIAL`、`UNVERIFIED` 都是迁移阻断项。
- 历史详细版的有效设计说明合并到本文末尾历史附录；当前事实区必须先由源码与工作树重新生成，历史状态不得覆盖它。

## 八、结构验收

- [ ] Java 对象数可从固定 SHA 重算。
- [ ] Rust 主文件排除 `lib.rs`、`mod.rs`、生成代码后可重算。
- [ ] 每个对象只有一个主要 Rust 文件。
- [ ] 所有生产、测试、示例、bench 与测试支持 `.rs` 文件均不超过 800 个物理行；501–800 行文件已有职责审查。
- [ ] 超长或弱内聚对象按职责拆分，子文件只实现同一 Java 对象，不引入第二迁移对象。
- [ ] 超过 Clippy 100 行信号的函数/方法已审查，未按行数机械拆分内聚算法。
- [ ] 聚焦私有行为的单元测试可位于 `#[cfg(test)]`；集成、差分、宿主、负载和整体验收测试位于 `tests/` 或测试包。
- [ ] 每个 Java 对象均按 `retain_segments={{RETAIN_SEGMENTS}}` 计算预期路径，错位文件标记为 `MISPLACED`。
- [ ] 每个重载和参数都有映射。
- [ ] 每个已有 Java 对象和方法注释都有 Rust 中文文档对应。
- [ ] 每个 `@param`（含泛型参数）、`@return`、`@throws`、`@since`、`@deprecated` 和相关 `@see` 都有明确去向。
- [ ] 关键 Java 行内/块注释已迁移到对应 Rust 分支或不变量附近。
- [ ] 对象和签名完整分母在编码前冻结。
- [ ] 状态与证据在整批实现冻结后的统一审计中批量更新，而非逐对象升级。
- [ ] 合并、拆分、重命名、排除和扩展均单列。
- [ ] 覆盖率分母未混入 BOM、聚合器、facade、测试支持或 Rust 扩展。
- [ ] 所有 `IMPLEMENTED` 行均有当前 Rust SHA 的文件/符号与可重放语义测试证据。
- [ ] 所有 `DEPENDENCY_REUSED` 行均有精确 crate、版本/提交、上游符号、本地调用点与集成测试。
- [ ] 所有 `PLATFORM_NA` 行均有平台专属证据，未用“生态已有”或“语义类似”代替。
- [ ] 只要存在 `MISSING`、`MISPLACED`、`STUB`、`PARTIAL`、`UNVERIFIED`，模块结论就保持未完成。
- [ ] 本表状态已与路线图、语义表和名称检查交叉核对。
